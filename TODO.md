# Cambios solicitados: experiencia docente y acceso en línea

- [x] **Vista docente separada y navegación superior.** Al entrar en modo docente, mostrar una experiencia visual diferenciada de la estudiantil; colocar arriba Vista previa, Lecciones, Quizzes, Estudiantes, Acceso al curso, Proyectos y Ajustes. Al salir del modo docente, restaurar la vista del estudiante.
- [x] **Nombre visible del docente.** Mostrar “Frank Marquez” en la experiencia docente como etiqueta visual, separada del correo autenticado y sin usarlo como identidad o autorización en Supabase.
- [x] **Inicio de sesión utilizable desde el primer uso.** Permitir escribir correo y contraseña sin tener que pulsar primero Configurar conexión. El botón Iniciar sesión docente configura Supabase automáticamente si la URL y la clave publicable del proyecto son válidas; la cuenta debe existir en Supabase Auth y el proveedor Email debe estar activo. Presentar errores de credenciales, correo sin confirmar o proveedor deshabilitado en español.
- [x] **Solicitudes de acceso visibles y accionables.** Mostrar Acceso al curso como pestaña superior; listar ahí solicitudes de estudiantes en tiempo real y permitir al docente conceder, denegar o revocar acceso por estudiante. La pestaña muestra un contador de solicitudes pendientes; las alertas del navegador requieren permiso y que la aplicación esté abierta y conectada (no hay Web Push para página cerrada).
- [x] **Código/enlace de aula claro.** Mostrar y permitir copiar el código de 12 caracteres además del enlace completo. El PIN local por sí solo no crea códigos ni aprueba solicitudes. Para gestionar solicitudes, el docente inicia sesión con la misma cuenta Supabase que creó el código del aula.
- [x] **Cámara directa para docente.** El docente puede iniciar la cámara desde su propio modo sin requerir una autorización interna de docente para sí mismo. Se conserva la solicitud de permiso nativa del navegador y los controles de consentimiento/autorización aplicables a estudiantes.
- [x] **Quizzes compartidos.** El quiz guardado por el docente se publica mediante RPC autenticada y queda disponible en Retos a los estudiantes aprobados de los grados seleccionados; la lectura valida la solicitud y el secreto aleatorio. El banco local se conserva, y la tabla solo almacena contenido didáctico.
- [x] **Migración Phase 13 aplicada en producción.** `supabase/phase-13-shared-quizzes.sql` se ejecutó en Supabase `scratchxr-lab`, rama `main` (Production), el 8 de noviembre de 2026. Verificación: tabla con RLS y sin lectura directa para `anon` ni `authenticated`; RPC docentes restringidas a docentes y RPC estudiantil validada por solicitud aprobada y secreto.
- [x] **Permisos de cámara individuales.** El docente puede conceder o revocar el uso de cámara a cada estudiante por separado, incluso autorizar solo a una persona. La autorización remota está vinculada a una solicitud aprobada; el permiso se deniega por defecto. No sustituye el consentimiento del estudiante ni el permiso del navegador. Los perfiles exclusivamente locales se administran solo en el navegador que los contiene. Los controles están en Acceso al curso.
- [x] **Migración Phase 14 aplicada en producción.** `supabase/phase-14-individual-camera-permissions.sql` se ejecutó en el mismo proyecto y rama el 8 de noviembre de 2026. Verificación: `camera_allowed` existe como `boolean NOT NULL DEFAULT false`; las tres RPC de cámara existen con privilegios de ejecución restringidos por rol.
